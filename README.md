# つぎの一作

6作ずつ出てくる設問で、見たことのある作品に☆1〜5を付けていきます。5問答えると、☆の評価から好みタイプと「次にハマりそうな作品」6作を診断するサイトです。
サーバーもAPIキーも不要で、内蔵カタログだけで動きます。
カタログは手書きの150作に加えて、[メディア芸術データベース](https://mediaarts-db.artmuseums.go.jp/)から取り込んだ漫画・アニメ・ゲームと、[TMDB](https://www.themoviedb.org/)から取り込んだ映画・ドラマ・アニメをおすすめに使います。このサイトは非商用です。

- 診断に使うのは☆の評価だけです。見ていない作品はそのまま次へ進めます。
- 設問には手書きの150作に加えて、取り込んだ作品のうち知られているもの(種類ごとに上位数百作)も出ます。各設問の6作には、手書きの作品が残っているあいだは手書きを2作入れます。取り込んだ作品のカードはひとことの代わりに発表年とタグを出します。
- 診断する種類(漫画・アニメ・映画・小説・ゲーム・ドラマ)はチェックボックスで選べます。複数選べます。
- 「泣ける」「考えさせられる」などのジャンルでもしぼれます。選ばなければすべてのジャンルから出します。
- 結果画面で「隠れた名作だけをおすすめする」にすると、印の付いた作品だけをおすすめします。
- 評価した作品は、次からの設問とおすすめに出なくなります。
- まだ見ていないけれど興味がある作品には「気になる」を付けておけます。☆を付けると自動で外れます。
- 評価はそのブラウザにだけ保存されるので、別の端末やブラウザとは共有されません。
- 結果画面の「データベースからも」には、取り込んだ作品のうち好みに合うものを最大6作出します。ひとこと紹介はまだなく、発表年とタグと出典へのリンクを出します。

> このリポジトリには、別の個人用ページ「辛口道場」(League of Legends の成績から自己紹介と辛口評価を作る遊び)も `lol/` に入っています。公開サイトには含まれず、`npm run lol` で自分のPCでだけ動きます。詳しくは [lol/README.md](lol/README.md)。

## 使い方(開発)

Node.js 20 以上が必要です。

```bash
npm install
npm run dev      # 開発サーバー(http://localhost:5173)
npm test         # テスト
npm run build    # 本番用ファイルを dist/ に出力
npm run preview  # dist/ の確認
```

## 構成

| ファイル | 役割 |
| --- | --- |
| `src/catalog.ts` | 手書きの作品カタログ(作品名・種類・好みタグ・ひとこと) |
| `src/imported.ts` | 取り込んだ作品の読み込み。題名の正規化と、手書きの作品との重なりの除去 |
| `src/tagmap.ts` | 元データのジャンル語から18タグへの対応表 |
| `scripts/import-madb.mjs` | メディア芸術データベースから作品を取り込むスクリプト(`npm run import`) |
| `scripts/import-tmdb.mjs` | TMDB から映画・ドラマを取り込むスクリプト(`npm run import:tmdb`) |
| `data/madb/`, `data/tmdb/` | 取り込んだ作品(生成物)。タグ付けできた `tagged.json`(TMDB のアニメは `anime.json`。サイトが読む)、件数の `summary.json`、対応表に当たらなかった語の `unmapped-genres.json` |
| `scripts/build-quiz-pool.mjs` | 取り込んだ作品から設問に出す候補を選ぶスクリプト(`npm run quiz-pool`) |
| `data/quiz-pool.json` | 設問に出す候補(生成物)。ページを開いたときに読む |
| `public/tmdb-logo.svg` | TMDB のロゴ(規約で表示が必要) |
| `src/quiz.ts` | 設問の進行(6作を引く、次へ、戻る、入れ替える。作品が少ないと短くなる) |
| `src/diagnose.ts` | 診断ロジック(☆の重みをタグごとに足して採点) |
| `src/filter.ts` | 種類・ジャンル・隠れた名作でのしぼりこみ。ジャンルは既存タグのまとまり |
| `src/seen.ts` | 見た作品と☆評価(付ける、外す、保存用の書き出しと読み込み、設問からの除外) |
| `src/interest.ts` | 「気になる」作品(付ける、外す、☆を付けたら自動で外す、保存用の書き出しと読み込み) |
| `src/main.ts` | 画面の描画 |
| `src/style.css` | デザイン(ライト/ダーク対応) |
| `tests/` | 進行・診断・取り込みのテスト |

## 作品を増やす

`src/catalog.ts` の `CATALOG` に1行足すだけです。

```ts
{ title: "作品名", media: "漫画", tags: ["冒険", "仲間"], pitch: "ひとこと紹介" },
```

広くは知られていないが評価の高い作品には `gem: true` を付けると、「隠れた名作」として扱われます。

- `tags` は既存のタグ(冒険・頭脳戦・切なさ など)から2〜4個選ぶと、診断の精度が保てます。
- 設問に最大30作使うので、作品が多いほど「6つとも知らない」で入れ替えられる回数が増えます。種類やジャンルをしぼったときに30作に満たないと、設問は短くなります。いまは各種類24〜26作、合計150作です。

### 外部データベースから取り込む

漫画・アニメ・ゲームは、文化庁・国立アートリサーチセンターの[メディア芸術データベース](https://mediaarts-db.artmuseums.go.jp/)が公開している[データセット](https://github.com/mediaarts-db/dataset)から取り込めます。

```bash
npm run import              # ダウンロード(.cache/ に保存)→ 変換 → data/madb/ に書き出す
npm run import -- --offline # .cache/ にあるものだけで変換し直す(対応表を直したとき)
```

- Node.js 22.18 以上が必要です(スクリプトが `src/tagmap.ts` と `src/imported.ts` を直接読みます)。プロキシ経由の環境では `NODE_USE_ENV_PROXY=1` を付けます。
- 取り込むのは、マンガ単行本シリーズ・アニメテレビシリーズ・アニメ映画シリーズ・ゲーム作品です。日本語の題名、種類、発表年、元データのID、元データのジャンル語を持ちます。成人向けの作品は入れません。
- メディア芸術データベースの漫画・アニメにはジャンルの項目がないので、[Wikidata](https://www.wikidata.org/)(CC0)のジャンルで補います。結び付けは、メディア芸術データベースのID(P7886)が同じ項目を優先し、なければ同じ種類の項目のうち正規化した題名がただ1つ一致するものを使います。
- ジャンル語から18タグへの対応は `src/tagmap.ts` にあります。自信のある対応だけを書き、「少年漫画」「学園もの」のような作風を決めない区分は対応させません。新しいタグは作りません。
- タグが1つも付かなかった作品は「未整備」として `tagged.json` には入らず、サイトには出ません。件数は `summary.json` にあります。未整備も含めた全作品は `.cache/madb/works/`(漫画だけで約20MB)に書き出すので、リポジトリには入れていません。対応表に当たらなかったジャンル語は `data/madb/unmapped-genres.json` に多い順で出るので、対応表を育てる参考にしてください。
- 取り込んだ作品は、結果画面の第2段のおすすめと「見た作品」に使うほか、知られているものは設問にも出します(下の「設問に出す候補」)。ひとこと紹介(`pitch`)は転載せず、独自に書くまで空のままです。
- 生成物はリポジトリに入れてあるので、ビルドやデプロイで外部に接続することはありません。元データが更新されたときや対応表を直したときに `npm run import` を実行し、生成物ごとコミットしてください。件数は `data/madb/summary.json` にあります。

### TMDB から映画・ドラマを取り込む

映画・ドラマと、日本のアニメ(テレビシリーズ)は [TMDB](https://www.themoviedb.org/) の API(v3)から取り込めます。

```bash
npm run import:tmdb              # 取得(.cache/tmdb/ に保存)→ 変換 → data/tmdb/ に書き出す
npm run import:tmdb -- --offline # .cache/tmdb/ にあるものだけで変換し直す
```

- API のリードアクセストークンが要りますが、スクリプトは鍵を読みません。実行する環境のプロキシが `api.themoviedb.org` への `Authorization` ヘッダーを付ける前提です(作業用のクラウド環境の network secrets に保存してあります)。鍵はリポジトリにも GitHub Actions にも置かず、ブラウザにも送りません。取り込みは CI では走らせません。
- 映画は「日本での公開日(劇場・配信・パッケージ・TV)が TMDB に登録されている作品」、ドラマは「日本で配信情報(JustWatch 提供)がある作品」と「日本制作の作品」の和集合です。どちらも人気順で `TMDB_MAX_PAGES`(既定 250)ページまで、票数の少ない作品と成人向けは除きます。判定に使った条件は `data/tmdb/summary.json` の `conditions` にあります。
- アニメは、ジャンルが Animation で日本の作品(制作国が日本か、原語が日本語)のテレビシリーズを「アニメ」として入れます。日本の作品なので配信情報は問いません。日本以外のアニメーション(海外のカートゥーンなど)は入れません(このサイトの「アニメ」は日本のアニメの意味で、「ドラマ」にも合わないため)。アニメ映画は手書きのカタログと同じく「映画」として入れ、「アニメ」には入れません。
- メディア芸術データベースのアニメと同じ題名の作品は、読み込み時(`src/imported.ts`)に TMDB の方を使います(ジャンルと keywords があってタグが付きやすく、日本での配信情報もあるため)。メディア芸術データベースの生成物は変えません。重なった件数は `data/tmdb/summary.json` の `overlapWithMadbAnime` にあります。
- ジャンル(日本語)と keywords(英語)を `src/tagmap.ts` の対応表で18タグに対応づけます。あらすじは使わず、`pitch` は空のままです。
- TMDB の規約に合わせ、画面のフッターに TMDB のロゴと「TMDB に承認・認定されたものではない」旨、配信情報の提供元として JustWatch のクレジットを出しています。画像(ポスター)は使いません。データは取得から6か月以内に取り直す決まりなので、`data/tmdb/summary.json` の `refetchBy`(取得日の約6か月後)までに `npm run import:tmdb` を実行してコミットしてください。

### 設問に出す候補

設問は「見たことがあるか」を答えるものなので、取り込んだ作品のうち知られているものだけを設問に出します。

```bash
npm run quiz-pool   # data/madb/ と data/tmdb/ の生成物から data/quiz-pool.json を作る
```

- TMDB の映画・ドラマ・アニメは `popularity` の高い順、メディア芸術データベースの漫画・ゲーム・アニメは Wikidata のサイトリンク数の多い順に、種類ごとに上位(漫画 220・アニメ 220・ゲーム 200・映画 220・ドラマ 220)を選びます。出典が2つあるアニメは、出典ごとの列を件数に応じた割合で交互に取ります(尺度の違う数を直接くらべない)。手書きの作品と同じ種類・同じ題名のものと、出典どうしで重なるもの(同じアニメなら TMDB を使う)は除きます。
- `data/quiz-pool.json` は 150KB ほどで、ページを開いたときに読みます。読めなければ、設問は手書きの150作だけで動きます。
- 各設問の6作は、シャッフルした山の先頭から取りますが、手書きの作品が山に残っているあいだは先に手書きを2作拾ってから残りを埋めます(`src/quiz.ts`)。種類・ジャンルのしぼりこみ、評価した作品の除外、「6つとも知らない」の入れ替えは、取り込んだ作品にも同じように効きます。
- 取り込みの生成物を作り直したら、`npm run quiz-pool` も実行してコミットしてください。

### 出典とライセンス

- 作品データの一部は、メディア芸術データベース(文化庁・独立行政法人国立美術館 国立アートリサーチセンター)のデータセットをもとにしています。このデータセットは自由な二次利用が可能です。このサイトでは、作品の抜き出し、同じ作品の版の統合、題名の整理、ジャンル語からの好みタグ付けなどの編集・加工をしており、その結果は元データの提供元によるものではありません。使った版は `data/madb/summary.json` の `source` に書いてあります。
- ジャンルの補いには Wikidata(CC0 1.0)を使っています。
- 映画・ドラマ・アニメ(日本のテレビシリーズ)のデータは TMDB の API から取得しています。メディア芸術データベースと同じ題名のアニメは TMDB の方を使います。このサイトは TMDB の API を使っていますが、TMDB に承認・認定されたものではありません(This product uses the TMDB API but is not endorsed or certified by TMDB)。日本での配信情報は JustWatch の提供です。TMDB の API は非商用の条件で使っており、このサイトは非商用です。

## 診断の仕組み

1. これまでに付けた☆の評価をすべて使います。今回の設問で付けたものに限りません。
2. ☆ごとの重みを、その作品のタグに足していきます。

   | ☆ | 5 | 4 | 3 | 2 | 1 |
   | --- | --- | --- | --- | --- | --- |
   | 重み | +1 | +0.5 | 0 | −0.5 | −1 |

   「気になる」を付けた作品のタグには、弱い手がかりとして +0.5(☆4と同じ)を足します。おすすめの元にはせず、おすすめからも外しません(出たときは印が付き、同点なら少し優先します)。
3. 点数の高いタグ上位2つが好みタイプ名(例:「SF×世界観派」)になります。
4. 評価していない作品を、タグの合計点と、☆4以上の作品とのタグの重なりで並べ、上位6作をおすすめします。おすすめの元になるのは☆4以上の作品だけです。
5. 好みの読み取りには全種類・全ジャンルの評価を使い、種類とジャンルのチェックは設問とおすすめだけをしぼります。隠れた名作だけの指定は、おすすめだけをしぼります。
6. 評価した作品は設問にもおすすめにも出しません。まだ評価していない作品が足りないときだけ、評価済みの作品をまぜて設問を作ります。☆を付け直せます。
