# つぎの一作

3作ずつ出てくる設問で好きな作品を好きなだけ(0〜3作)選び、10問答えると、好みタイプと「次にハマりそうな作品」6作を診断するサイトです。
サーバーもAPIキーも不要で、内蔵カタログだけで動きます。

見た作品は☆1〜5で評価できます。評価した作品は、次からの設問とおすすめに出なくなります。☆5の作品は、設問の「好き」と同じく好みの診断にも使います。評価はそのブラウザにだけ保存されるので、別の端末やブラウザとは共有されません。

## 使い方(開発)

Node.js 20 以上が必要です。

```bash
npm install
npm run dev      # 開発サーバー(http://localhost:5173)
npm test         # テスト
npm run build    # 本番用ファイルを dist/ に出力
npm run preview  # dist/ の確認
```

## 構成

| ファイル | 役割 |
| --- | --- |
| `src/catalog.ts` | 作品カタログ(作品名・種類・好みタグ・ひとこと) |
| `src/quiz.ts` | 設問の進行(3作を引く、好きを付け外す、次へ、戻る、入れ替える) |
| `src/diagnose.ts` | 診断ロジック(タグの重なりで採点) |
| `src/seen.ts` | 見た作品と☆評価(付ける、外す、保存用の書き出しと読み込み、設問からの除外) |
| `src/main.ts` | 画面の描画 |
| `src/style.css` | デザイン(ライト/ダーク対応) |
| `tests/` | 進行と診断のテスト |

## 作品を増やす

`src/catalog.ts` の `CATALOG` に1行足すだけです。

```ts
{ title: "作品名", media: "漫画", tags: ["冒険", "仲間"], pitch: "ひとこと紹介" },
```

- `tags` は既存のタグ(冒険・頭脳戦・切なさ など)から2〜4個選ぶと、診断の精度が保てます。
- 設問に30作使うので、作品が多いほど「3つとも知らない」で入れ替えられる回数が増えます。

## 診断の仕組み

1. 「好き」と選んだ作品と☆5を付けた作品のタグを +1、選ばなかった作品のタグを −0.3 で集計します。ひとつの設問で何作選んでも、それぞれ +1 です。同じ作品が「好き」と☆5の両方に当たっても、数えるのは1回です。
2. 点数の高いタグ上位2つが好みタイプ名(例:「SF×世界観派」)になります。
3. 選んだ作品を除くカタログ全作を、タグの合計点で並べて上位6作をおすすめします。設問で選ばれなかった作品は減点されます。
4. 10問でひとつも選ばなかった場合は傾向を読めないので、おすすめは出さず「選び直す」を促します。
5. ☆で評価した「見た作品」は、設問にもおすすめにも出しません。見ていない作品が30作を切ったときだけ、足りない分を見た作品で埋めて設問を作ります。設問にまざった☆5の作品は、選ばなくても減点しません。☆1〜4の評価は採点に使っていません。

## 公開(GitHub Pages)

`main` に push すると、GitHub Actions がテスト・ビルドして GitHub Pages に公開します。
初回だけ、リポジトリの Settings → Pages → Source を「GitHub Actions」にしてください。
